## Алерти переписані (2026-08-28)

Було: `• ядро (12 активів) 0x1234abcd CEX→binance $3021456`. Стало — чотири розділи:

1. **ХТО І КУДИ ПЕРЕВІВ** — поіменно: адреса-відправник з роллю, адреса-отримувач з міткою
   (`Binance 14`, `Bitfinex: Hot Wallet`), кількість у токенах, сума в доларах, ціна,
   посилання на транзакцію. Усі адреси клікабельні.
2. **КУДИ ПІШЛО** — зведення за адресами-отримувачами.
3. **МАСШТАБ ВІДНОСНО РИНКУ** — частка денного обігу, частка ліквідності пулів, частка
   капіталізації, і оцінка просідання за `x·y=k`, якби обсяг пішов у пул одним свопом.
4. **ЩО ЦЕ ЗНАЧИТЬ** — інтерпретація на ВЛАСНИХ виміряних базах (`cexemis`: медіана −7.6%
   після заводів на біржу) плюс явне застереження про межі (`flowbt`: AUC 0.49 — потік
   НЕ передбачає напрям ціни).

`campwatch` додатково ходить за вихідними переказами холдера (`latest_txs`), щоб сказати
не лише «вивів 89%», а й на які саме адреси. `wakeup` показує транзакцію, якою гаманець
ожив, і окремо виділяє тих, хто пішов на біржу.

### Три пастки, знайдені на попередньому перегляді

| Пастка | Чому важлива |
|---|---|
| Дві ціни на той самий токен в одному листі (ENA $0.136 з DefiLlama проти $0.156 з GeckoTerminal) | лист, що сам собі суперечить, перестають читати. Тепер ціна одна — та, з якої порахована сума |
| ETH отримував «ринкових даних нема» | це була найбільша позиція листа. Мовчати про головне гірше, ніж сказати, що обмеження не тут |
| «13% ліквідності» і «просідання ~36%» поруч, з висновком «ринок здатен усмоктати» | дві міри суперечили одна одній. Вердикт тепер один і рахується від глибини пулу — саме в неї впирається продаж |

Режим перегляду: `DRY=1` складає повідомлення повністю й друкує в stderr замість каналу.
Без нього налаштувати текст можна було б лише розсилаючи його собі.

## Дві поломки, знайдені під час переведення

1. **`cexsignal` був мертвий 7 днів.** 19.08 ключі Etherscan переїхали з `.env` у
   `deploy/backfill.env` (права 600). Бін читав лише `.env`, тож із 19.08 12:48 тричі на
   годину писав «нема BACKFILL_ETHERSCAN_KEYS» і виходив з кодом 0 — ~500 холостих запусків.
   Cron-лог ріс, ніхто не бачив. Виправлено в шарі: `find_keys` шукає в оточенні →
   `deploy/backfill.env` → `.env`.
2. **`token-prices.json` був 0 байт** з 23.08, хоч лог `tokprices` казав «збережено».
   Будь-який запуск `cexsignal` після цього падав би панікою на розборі цін. Файл
   перезібрано (36 КБ, 265 токенів).

Обидві — одного роду з тими, заради яких шар і робиться: **тихий збій, який виглядає як
робота**. Ні перша, ні друга не мали б шансу протриматись тиждень, якби протокол доступу
був один і сам гучно скаржився.

## Навіщо

32 біни ходять в експлорери, 28 із них — прямо в Etherscan, кожен зі своєю копією
протоколу. Копії розійшлися, і це вже коштувало двох тихих псувань даних:

- **NOTOK як HTTP 200** — 13 бінів зараховували ліміт як «подій немає» (аудит 2026-07-31);
- **`offset=10000`** — 6 бінів мовчки отримували 1000 записів замість повної історії.

Обидва дефекти одного роду: знання жило в 32 місцях, тож забути його можна було 32 рази.
Тепер протокол один — `backfill::chain`.

Другий мотив — перехід на власну ноду. Коли з'явиться NVMe і Erigon, це буде
`CHAIN_SOURCE=node` в оточенні, а не правка 32 файлів.

## Що всередині

`rust-new/chain.rs`, зареєстровано в `lib.rs` як `pub mod chain`.

| Що | Навіщо |
|---|---|
| `ChainSource::from_env(root, chain)` | збирає джерело: `CHAIN_SOURCE` → `API_BASE` → ключі → `RPC_URLS`; без джерела — паніка одразу, а не нуль рядків як «результат» |
| `Kind` (`Ext`/`Int`/`Tok`) | назви збігаються з полем `k` у `txfull-<chain>.jsonl` — формат даних на диску не міняється |
| `Tx` + `to_json()` | рядок ІДЕНТИЧНИЙ поточному txfull: `{w,k,ts,h,f,t,v,tok,sym,dec,gas,gp,nonce,err}` |
| `txs_page()` | одна партія; `None` = не відповіли, `Some(vec![])` = подій немає |
| `txs_all()` → `Pull{txs, complete}` | повна історія просуванням стартового блоку + зняття дублів на межі вікна |
| `code` / `is_contract` / `eth_balances` / `token_balance` / `token_supply` / `block_number` / `block` / `logs` | решта викликів, що зустрічались у бінах |
| `Quota` | token-bucket **на все джерело**, 3 rps типово; ретрай теж бере слот |

### Три рішення, які варто пам'ятати

1. **`Option` замість `Vec`, скрізь.** `None` ≠ порожньо. Це головне правило модуля;
   саме його порушення дало гаманці, назавжди позначені `done` з нулем рядків.
2. **`page` жорстко обрізано до 1000.** Навіть якщо задати `PAGE=10000`, буде 1000 —
   бо сервер саме стільки й віддає, просто мовчки.
3. **Обмежувач один на процес, не на ключ.** Ліміт Etherscan — 3 req/s і 100k/добу,
   і **ретрай списується теж**. Коли кожен бін розганявся сам, паралельні біни
   складались і разом виходили за стелю — так згоріло 8 із 9 ключів.

### enum, а не `dyn Trait`

Async-функції в трейтах не дають object safety без крейта `async-trait`. Заради трьох
реалізацій нову залежність не додавав — enum-диспетч коштує один `match` і не міняє
`Cargo.toml`.

## Як переводити бін (рецепт)

**Було** (txfull, ~35 рядків на бін):

```rust
async fn batch(client, keys, kc, chain, api, action, w, from_block) -> Option<Vec<Value>> {
    for attempt in 0..7u64 { /* ротація ключів, is_limited, backoff */ }
    None
}
// ... у main: цикл вікон, from_block = last_block, arr.len() < 1000, failed-прапорець
```

**Стало**:

```rust
use backfill::chain::{ChainSource, Kind};

let src = ChainSource::from_env(&root, chain);
let kinds = Kind::parse_list(&std::env::var("KINDS").unwrap_or_else(|_| "ext,int,tok".into()));

let pull = src.txs_all(&w, &kinds).await;
let lines: Vec<String> = pull.txs.iter().map(|t| t.to_json().to_string()).collect();
// пишемо зібране завжди (append + дедуп по hash далі),
// done — ЛИШЕ при pull.complete
if pull.complete { writeln!(donef, "{w}")?; }
```

Порядок дій на бін:

1. Викинути локальні `batch`/`es`/`get_json`, `keys`, `kc`, `envv`, ручний backoff.
2. Один `ChainSource::from_env` на процес, у `Arc`, спільний на всі задачі.
3. Замінити виклик на метод шару.
4. **Перевірити місце, де пишеться `.done`** — воно має залежати від `complete`/`Some`.
5. Прибрати штучні `sleep` між вікнами: квоту тримає `Quota`, а на своїй ноді паузи
   зайві (`src.is_metered()`).

### Черга переведення

Спершу те, що в cron і псує дані щодня:

1. `cexsignal`, `cexcrawl`, `campwatch`, `livewatch`, `wakeup` — у cron.
2. `txfull`, `txmass`, `eth_edges2` — основні краулери, дають дані решті.
3. `ethbal`, `realbal`, `tokbal2`, `toksupply` — стан, від них залежать усі $-оцінки.
4. Решта аналітичних (`rhythm`, `gasprint`, `eventstudy`, `sellstudy`, …) — за потребою.

Переводити по одному, звіряючи вихід зі старим на тих самих адресах. Спокуса
«перевести всі 32 за раз» тут — прямий шлях до непомітного зсуву в даних, на яких
уже стоять висновки.

## Що НЕ зроблено і потребує ноди

Гілка `Backend::Node` написана, але **не перевірена на живій ноді** — своєї ще немає.

| Вид | Метод | Ризик |
|---|---|---|
| `ext` | `ots_searchTransactionsAfter` (Otterscan, вбудований в Erigon) | розбір полів за специфікацією, не за живою відповіддю |
| `int` | `trace_filter`, два напрями окремо | `ts` не приходить — час треба брати з блоку |
| `tok` | `eth_getLogs` по topic0=Transfer | `sym`/`dec` нода не знає: це метадані контракту, окремий виклик |

Перед тим як довіряти цифрам з ноди — прогнати десяток відомих адрес і **звірити з
Etherscan рядок у рядок**. Розбіжність у `ts` для int/tok очікувана і має бути закрита
підстановкою часу блоку, а не проігнорована.


Чого не знаю, бо ВМ не відповіла:

- чи `reqwest`/`tokio`/`serde_json` уже в `[dependencies]` крейта `backfill` — швидше за
  все так (біни в тому ж крейті ними користуються, а біни ділять залежності крейта),
  але перевірити треба;
- чи крейт `nextaction` має залежність на `backfill` — якщо ні, для його бінів
  (`rgbridge`, `rgnull5`) треба додати `backfill = { path = "../backfill" }`.

Аудит вважати закритим **лише після успішної збірки** — як і в попередній раз.
